# Issue: Navegação direta e seamless — campo de página, teclado e setas instantâneas

**Título sugerido:** `feat(nav): navegação direta — ir para página, teclado, vizinho pré-renderizado`
**Labels:** `enhancement`, `ui`, `navigation`, `ux`
**Prioridade:** alta — base de navegação do visor

---

## Resumo

Hoje a navegação do Tsuro é de página única (Single Page): painel de miniaturas + chevrons ◀▶ + busca. O contador `3 /42` na pílula é label estático — não dá para digitar a página. Não há atalhos de teclado. E cada clique na seta pode pagar render novo do zero (o cache descarta tudo exceto a página visível), então **voltar** uma página mostra "Renderizando página…". Esta issue torna a navegação direta (digitar página) e seamless (seta sem flicker), mantendo o engine Pdfium **inalterado** — mudanças só em `session.rs` (estado/cache) e `view.rs` (pílula).

## Motivação

- **Direta**: leitor que sabe a página (contrato assinado na p. 7) precisa de 3 cliques hoje (⋯ → ? → setas) — sem caminho digitável.
- **Seamless**: o #21 garantiu bitmap antigo durante re-render de zoom; o mesmo espírito falta na navegação — ir e voltar não deve piscar.
- **Teclado**: padrão de leitores (Adobe, Okular, pdf.js); ausência completa hoje.

## Princípios (não negociáveis)

1. Engine Pdfium **inalterado** (regra AGENTS); mudanças em `session.rs` + `view.rs` + `kiri.rs` (ícones novos se preciso).
2. `PageNo` é 0-based (`PageNo::first()` = 0) — nenhuma matemática 1-based inventada.
3. Seamless por **cache/pré-render**, não por bloqueio.
4. Pílula continua o trilho central (kiri-spec): campo cabe nela, sem segunda barra.

## Estado atual vs alvo

| Aspecto | Hoje | Alvo |
|---|---|---|
| Ir para página | Label `3 /42` estático | **Input digitável** na pílula (Enter navega, clamp 1..n) |
| Teclado | Nenhum (só FileDropped/Opened) | PgUp/PgDn ◀▶, Home/End 1ª/última (guardado por foco em input) |
| Voltar página | Pode re-render do zero ("Renderizando…") | Cache retém `visible` ± 1; vizinho pré-renderizado em idle |

## Implementação (fases da issue — PRs)

### A. Campo "ir para página"
- `session.rs`: `Ready.page_input: String` (draft) + `Message::PageInput(String)` + `Message::PageSubmit`.
- `PageSubmit`: parse 1..=n; vazio/lixo → ignora e restaura; válido → `SetPage`, limpa draft. `SetPage` por outra via sincroniza o draft (input controlado).
- `view.rs` topbar: label vira `text_input` estreito (~48px, centrado, enter-to-submit) + `/n` `muted`.

### B. Teclado
- `session.rs` subscription: `Event::Keyboard` via `event::listen_with` (já usado).
- Função pura `fn keyboard_message(key: Key, mods: Modifiers) -> Option<Message>` → teste unitário.
- `PageUp`/`PageDown` = anterior/próxima; `Home`/`End` = primeira/última **somente quando nenhum `text_input` focado** (guardar por foco; verificar API de foco iced 0.13 via Context7 na implementação).
- Não conflita com digitação: `PageUp/Down` não são teclas de edição; `Home/End` precisam do guard.

### C. Seta seamless (vizinho pré-renderizado)
- `session.rs` `evict_unused`: `retain_pages(|p| p == visible)` → retém `visible ± 1`.
- Pré-render: quando a página visível renderiza, agenda render da próxima (`visible+1`) via `request_render` generalizado; bitmap chega ao cache em idle — clique ▶ não bloqueia.
- Regressão: #21 (`zoom_change_keeps_old_bitmap_until_rerender`) e `evict_unused` devem continuar verdes.

## Testes (regra: comportamento, não plumbing)

- (A, sem fixture) submit "0", "9999", "", "abc", "7" → transições corretas; draft sincroniza após `SetPage` externo.
- (B, sem fixture) `keyboard_message`: PgDn→next, PgUp→prev, Home→first, End→last; com search focado → `None`.
- (C, fixture `sample_ready`) ▶ seguido de ◀ sem novo `Rendered` (cache ±1); evict mantém vizinhos.
- Suíte completa `cargo test -p tsuro` verde; smoke manual com `guia-folio.pdf` ida-e-volta.

## Definition of Done

Issue fechada quando PRs A–C mergeados, critérios acima marcados, smoke manual ida-e-volta sem "Renderizando…" no caminho de volta.
