# Issue: Modos de página — rolagem contínua e espelhadas (facing)

**Título sugerido:** `feat(view): modos de página — rolagem contínua e espelhadas`
**Labels:** `enhancement`, `ui`, `view`, `ux`
**Prioridade:** média — depois da navegação direta (base), antes ou junto da impressão

---

## Resumo

O Tsuro é **Single Page** (página única com scroll interno por página). Leitores maduros oferecem a mesma taxonomia da Adobe (Single Page / Single Page Continuous / Two Page / Two Page Scrolling, com capa separada opcional). Esta issue adiciona **Rolagem contínua** (todas as páginas empilhadas, uma coluna) e depois **Espelhadas contínuas** (pares lado a lado, capa sozinha). Terminologia na UI pt-BR: **Página única · Rolagem contínua · Espelhadas** — evitar "two-up" (ambíguo com impressão: 2 páginas por folha).

## Motivação

- Documentos longos leem melhor em fluxo contínuo (padrão dos leitores modernos e do PDF.js — ScrollMode `VERTICAL`, `WRAPPED`, spread `ODD/EVEN`).
- Contratos/livros pedem espelhadas com capa separada (Okular "Facing Pages (Center First Page)", SumatraPDF "Book view", Foxit "Continuous Facing" + "Separate Cover Page").
- Pdfium inalterado: páginas já são renderizadas por página; o modo é geometria de layout + derivação de `visible` do scroll — sem tocar no motor.

## Princípios (não negociáveis)

1. **Engine inalterado.** Tudo em `view.rs` (layout) + `session.rs` (estado de modo, derivação de página visível, cache).
2. **Virtualização**: páginas fora da viewport viram containers de altura proporcional à mídia — **nunca** montar N bitmaps nem N widgets completos (padrão já usado no painel de miniaturas com `THUMB_ROW`).
3. **Modo é estado persistível?** Não nesta issue — começa sem persistir (decisão futura com tema). Fica em `Ready.view_mode`.
4. Zero gradiente/glass; folha branca sempre (kiri).
5. `visible` derivado do scroll em modo contínuo; `SetPage`/busca saltam o scroll (infra `scroll_to`/restore já existe — reutilizar).

## Estado atual vs alvo

| Aspecto | Hoje | Alvo |
|---|---|---|
| Layout | 1 página centralizada | 1 por tela / coluna contínua / pares |
| Página visível | `Ready.visible` explícito | Derivada do offset em contínuo |
| Cache | `visible ± 1` (após nav direta) | Janela de viewport (mesma regra, dimensão extra) |
| Alternância | — | Menu ⋯ → "Modo de página" (Página única / Rolagem contínua / Espelhadas) |

## Wireframe (contínuo)

```text
┌───────────────────────────────────────────┐
│  ┌──────────────┐  ← p.3 (visível, ativa) │
│  │   PDF 3      │  render completa        │
│  └──────────────┘                         │
│  ⠇ placeholder altura p.4 (vazio)         │
│  ┌──────────────┐  ← p.4 entra no clip    │
│  │   PDF 4      │  render sob demanda     │
│  └──────────────┘                         │
└───────────────────────────────────────────┘
```

Espelhadas: capa sozinha (centralizada), depois p.2+3, 4+5… — pares como células de uma grade de 2 colunas.

## Implementação (fases da issue — PRs)

1. **`ViewMode` enum** em `session.rs` (`Single` | `Continuous`); `Ready.view_mode`; `Message::SetViewMode`; item no menu ⋯ ("Modo de página") — sem mudança de layout ainda (migração segura).
2. **Layout contínuo**: `ready_body` monta coluna de placeholders proporcionais (altura = `page_count × media` na escala atual); render só das páginas no viewport; `visible` = primeira página no clip. `SetPage`/busca → `scroll_to(offset da página)`.
3. **Espelhadas (facing)**: célula de 2 páginas (L/R) por linha; capa isolada; grid de 2 colunas dentro do scroll contínuo; mesma virtualização.
4. Testes + smoke com `guia-folio.pdf` (ida-e-volta, zoom, busca saltando em contínuo, painel de miniaturas sincronizado).
