# Issue: Impressão — PDF de impressão (200 DPI) sem diálogo nativo

**Título sugerido:** `feat(print): imprimir como PDF de impressão (~200 DPI)`
**Labels:** `enhancement`, `print`, `ux`
**Prioridade:** média — depois da navegação (missão atualizada inclui imprimir; forma leve aprovada)

---

## Resumo

Adicionar **Imprimir** ao Tsuro na forma **leve**: renderizar as páginas pela engine existente em ~200 DPI e montar um **PDF de impressão** com o crate `printpdf`; o PDF abre no visualizador padrão do sistema (Preview) e o usuário imprime de lá. Sem diálogo nativo de impressão (sem FFI por SO), sem nova superfície de suíte.

**Decisão registrada (2026-09-08)**: missão atualizada para "ler, anotar, marcar, **imprimir**" (AGENTS.md + README.md já alterados). Forma escolhida: leve. Nativo (objc2/NSPrintOperation, windows PrintDialog) fica como possível evolução futura, não nesta issue.

## Motivação

- Usuários esperam imprimir contrato/artigo do leitor.
- iced 0.13 **não tem** diálogo de impressão nativo; comunidade usa `printpdf` para gerar PDF (sem FFI, cross-platform).
- O Tsuro já renderiza páginas em qualquer escala (`engine.render(page, scale)`) — a impressão é um re-render em DPI alto + empacotar em PDF; Pdfium intacto.

## Princípios (não negociáveis)

1. Engine Pdfium inalterado — reusa `render(page, scale)` com `Scale` de ~200 DPI.
2. **Uma** dependência nova (`printpdf`); pedir aprovação antes de adicionar (regra AGENTS "Ask first: new dependencies").
3. Sem diálogo nativo, sem drivers, sem job de impressão — o Tsuro **gera** o PDF de impressão.
4. Sem suíte: sem escolha de impressora/páginas por intervalo na v1 — opções mínimas vêm depois se a demanda justificar (decisão futura).
5. PDF de impressão = páginas no tamanho da folha real (MediaBox), como qualquer leitor faz.

## Estado atual vs alvo

| Aspecto | Hoje | Alvo |
|---|---|---|
| Imprimir | Não existe | Menu ⋯ → **Imprimir** (ícone Ori novo) |
| DPI | Render em escala de tela | Re-render ~200 DPI (Scale::from_factor) |
| Saída | — | `printpdf` → PDF temporário → `open` no visualizador padrão (macOS/Windows) |
| Thread | — | Render fora da UI (padrão engine: `spawn_blocking`) |

## Wireframe (fluxo)

```text
⋯ → Imprimir
      │
      ▼
render cada página @ ~200 DPI (engine, spawn_blocking)
      │
      ▼
monta PDF (printpdf) com MediaBox por página
      │
      ▼
abre no visualizador padrão (Preview) → usuário imprime/salva
```

## Implementação (fases da issue — PRs)

1. **Dependência + preparação**: `printpdf` no workspace (com aprovação); função pura `print_pages(ready, dpi) -> Vec<render jobs>`; testável sem IO.
2. **Render + montagem**: loop `engine.render(page, Scale 200dpi)` em `spawn_blocking`; mapeia bitmaps → páginas `printpdf` com o MediaBox original; estado `Printing { progress }` opcional no `Session` (feedback sem travar UI).
3. **Disparo + abertura**: `Message::Print` no menu ⋯; escreve PDF em cache temporário; `open`/`start` no visualizador padrão (macOS `open`, Windows `cmd /c start`); tratamento de falha com `Failed`-like amigável.

## Testes

- (1, sem fixture) `print_pages`: N páginas → N jobs na ordem, com scale 200dpi, sem IO.
- (2, fixture) monta PDF de impressão de `guia-folio.pdf` em memória; reabre com `tsuro-sign`/parser e confere contagem de páginas + MediaBox (teste de integração pequeno).
- (3) sem teste de UI nativa: smoke manual — imprimir abre Preview com o PDF correto.
- Suíte completa `cargo test -p tsuro` verde.

## Definition of Done

Issue fechada quando PRs 1–3 mergeados, critérios marcados, smoke manual no macOS: ⋯ → Imprimir → Preview abre o PDF de impressão com as mesmas páginas/MediaBox do original.
